# 可変刻み計算とパラメータ掃引

ブロック図エディタの「シミュレーション設定」で固定刻み RK4／可変刻み RK45 を選びます。PID Lab は従来の計算方式を維持します。モデルの `solver` を省略すると従来どおり RK4 です。旧モデル・旧実行結果の JSON に新しいフィールドを自動追加しません。

## 時計と精度

RK45 は Dormand–Prince 5(4) の7段法で、連続状態全体を結合して積分します。5次／4次の推定差を各成分の `abs_tolerance + rel_tolerance × max(|開始状態|, |終了状態|)` で割り、最大比が1以下のステップを受理します。棄却時は状態を戻し、刻みを小さくして再試行します。これは局所誤差の推定で、全記録点の真の誤差や閉ループの安定性を保証しません。

`dt` は記録時計です。内部刻みは独立に適応させ、ステップ内の記録点は4次の dense output で求めます。記録時刻は常に `i × dt` で、終了時刻はその整数倍です。内部刻みが `dt` より大きくても、Scope の記録点を間引きません。

```json
"solver": {
  "method": "rk45",
  "abs_tolerance": 1e-9,
  "rel_tolerance": 1e-9,
  "min_step": 1e-12,
  "max_step": 0.8
}
```

上はモデル内のフィールドの説明です。絶対許容誤差・最小／最大刻みは有限の正数、相対許容誤差は0〜1、最小刻みは最大刻み以下とします。最小刻みで精度を満たせない場合はエラーです。浮動小数点の分解能で時刻が進まない場合も終了し、成功した結果として返しません。

Step の切り替え時刻と離散 PID／Delay の更新時刻で積分区間を分割します。Step 端点の微分評価は左極限を使い、次の区間から新しい値を使います。イベントや終了点に正確に着地するための短い区間だけは `min_step` 未満を許します。一般のゼロクロッシング検出ではありません。

離散周期は `dt` の整数倍で、従来の同期更新・出力保持・Delay の保留入力の反映順序を維持します。棄却した微分評価で離散状態を更新しません。連続状態がないモデルでは内部積分を行わず、記録時計で直接評価します。

計算方式はルートとサブシステムで共有します。子の指定は省略またはルートと完全一致が必要です。GUI の変更は子の上書きを取り除き、1回の Undo で戻せます。コピー／追加読み込みは同じ記録時計・計算方式・許容誤差・内部刻みのモデル同士で行います。省略 RK4 と明示 RK4 は同じ方式です。

RK4 の `dt <= tau/2`、`dt <= derivative_tau/2` 条件は従来どおりです。RK45 は記録時計にこの条件を要求せず、内部刻みと誤差推定で制御します。剛性ソルバではなく、非常に速い系・厳しい許容誤差では処理上限に達する場合があります。

## 統計と保存

Scope に、受理した積分回数、棄却回数、微分評価回数、記録評価回数、内部刻みの最小／最大値を表示します。RK45 は最大の受理誤差比も示します。明示的に計算方式を指定した結果には `statistics` を保存します。省略 RK4 の表示用統計は記録時計と Step 分割から求め、旧結果 JSON は変更しません。計算方式・許容誤差はモデル JSON／ブラウザ保存へ、統計は実行結果ファイルへ保存し、読み込み時には全記録点に加え統計も再計算と一致することを確認します。

RK45 は100000回の受理・棄却試行と、2000万ブロック成分評価を上限とします。評価回数は記録評価も含め、階層展開後の全ブロックの幅を乗じて数えます。録画や CSV の表示系列数によらず、全モデル・全結果に適用します。

## 掃引の操作

1. 「パラメータ掃引」を開き、対象ブロックとパラメータを選びます。入れ子は `amplifier/gain` のような正確なパスで区別します。ベクトルの各成分も選べます。
2. 有限な数値を1〜32個の JSON 配列で指定します。anti-windup の真偽値は `[0,1]`。上下限を解除する `null`、トポロジー・信号幅・ソルバの掃引はこの形式では扱いません。
3. 評価 Scope・成分・一定の目標値と、記録時計に揃った開始／終了時刻を指定します。
4. 「掃引を実行」で各ケースを独立に複製・検証・計算します。元のモデル・現行結果・基準・編集履歴・未保存判定は保持します。
5. 各行の「基準にする」は比較基準へ結果を保持します。「設定を適用」はそのケースの実行時モデル全体と結果を適用し、1回の Undo で戻せます。未保存モデルの置き換え確認は従来と同じです。

表には評価窓の終点・最小／最大値、台形則による IAE `∫|出力−目標|dt` と ISE `∫(出力−目標)²dt`、実際の微分評価回数を示します。IAE／ISE は指定した記録窓の指標で、一般の整定時間や最適チューニングの判定ではありません。有限値で表せない指標はエラーにし、Infinity を成功値として出力しません。

パラメータ検証の失敗はその行へ記録し、後続ケースを続けます。数値計算の失敗では残りの行を未実行として記録します。実際の評価予算は全ケースで2000万回を共有し、残り予算を WASM に渡して上限前に停止します。記録量は全ケースで200万セルまで、従来のモデルごとの上限も維持します。

「掃引を中止」とモデル編集はワーカーを終了し、完了済み行を保持、残りを未実行とします。古い返答は反映しません。通常の実行／結果ファイル読み込みと掃引は同時に起動しません。完了した掃引結果は編集後も実行時の設定で保持し、ページ再読み込みでは消えます。

「掃引設定を保存」は現在のフォームとモデルを version 1の `blocksim.sweep` JSON に保存します。1 MB以下のファイルを読み込むとモデルとフォームを復元し、実行は明示操作で行います。結果そのものの保存は各ケースを適用して実行結果ファイルへ保存してください。「掃引 CSV」は実行時の評価条件と全行を出力し、エラー／未実行行も含めます。

## 再現モデル

GUI のモデルサンプルから4つの RK45 モデルを選べます。Rust でも再現できます。

```bash
source scripts/rust-env.sh
cargo run --locked -p blocksim-core --example numerics
```

| モデル | 比較対象 | 最大絶対誤差 | RK45／比較側の微分評価 |
|---|---|---:|---:|
| 一次遅れ、1001点 | `1−exp(−t/0.25)` | 3.87e−10 | 609／4000 |
| 結合振動子、601点 | `cos(t)` | 1.82e−10 | 1036／2400 |
| 0.015秒の Step、11点 | `2 max(0,t−0.015)` | 8.88e−16 | 28／44 |
| 混在 PID、4001点 | 記録時計 `dt/4` の RK4 | 1.05e−10 | 5607／64000 |

詳細な出力は [numerics-validation.json](numerics-validation.json)。一次遅れでは微分評価を84.775%減らしました。これは評価回数の比較で、実時間の高速化率ではありません。混在モデルは比較側の時計を4倍細かくしている点も含めて解釈してください。別のモデルで同じ効率や誤差を保証しません。

[PID 掃引サンプル](../samples/sweeps/pid-anti-windup.json) を「掃引設定を読み込む」で開くと、目標を5秒で3から0.5へ下げ、AW 無効／有効の復帰 IAE 約10.49／0.65を比較できます。
