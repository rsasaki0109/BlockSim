# Discrete Rate Limiter

指定周期Tsごとに、出力の上昇・下降の変化量を別々に制限します。各信号成分は独立で、速度設定は全成分へ共通に適用します。t=0の出力は指定した初期値、最初の更新はt=Tsです。更新時点の現在の入力を読み、次の更新まで出力を保持します。

```text
y[0] = initial
rise = rising_rate × Ts
fall = falling_rate × Ts

y[n] = 前の出力から、現在の入力へ最大riseだけ増加／最大fallだけ減少
```

1更新の差分は `−fall ≤ y[n]−y[n−1] ≤ rise` です。上昇・下降速度は0以上の有限スカラーで、下降速度は正の大きさを指定します。上昇速度0は増加のみ停止、下降速度0は減少のみ停止、両方0は初期出力を保持します。入力へ届いた後は、それ以上進めず入力と同じ値になります。

これは**離散更新間の変化量制限**です。保持した出力は更新時に段差を持つため、連続時間の傾きが有限になることや、連続Rate Limiterと同じ波形を保証しません。

## GUIと保存

ブロック種類の「Discrete Rate Limiter」を追加し、上昇速度・下降速度・初期値のJSON配列・サンプル周期・信号幅を設定します。既定は速度1／1、初期値[0]、信号幅1、周期はモデルの記録刻みです。

```json
{"kind":"discrete_rate_limiter","rising_rate":2,"falling_rate":1,"initial":[0,0],"sample_time":0.125}
```

初期値は幅1〜64と同じ長さの有限配列。周期は記録刻みの整数倍（1〜100000倍）で、速度×周期は表現可能な有限の増分が必要です。正の速度から増分が0へアンダーフローする設定も拒否します。速度・周期・初期値は必須で、未知項目は拒否します。

通常のUndo／Redo、モデルJSON、ブラウザ保存、サブシステム内部の境界入出力で設定を保持します。保存するのは初期値で、前回実行の最終状態から自動で再開しません。通常の再実行は初期値から開始します。上昇・下降速度、初期値の各成分、周期はパラメータ掃引の選択候補にも含まれます。不正な適用やファイル読み込みでは直前のモデルと完了結果を保持します。

## サンプルと数値

GUIの「ベクトル目標値の変化量制限」は[2成分サンプル](../samples/graphs/rate-limiter.json)を開きます。上昇速度2・下降速度1・Ts=0.125秒なので、1更新の最大増分は0.25、最大減分は0.125。記録刻み0.025秒、終了3.75秒、全151点を元の入力と処理後の別Scopeへ記録します。

| 時刻 | 元入力 | 制限後 |
|---|---|---|
| 0 | [1, −1] | [0, 0]（初期値） |
| 0.125 | [1, −1] | [0.25, −0.125] |
| 0.5 | [1, −1] | [1, −0.5] |
| 1.0 | [1, −1] | [1, −1] |
| 1.5 | [−1, 1]へ変更 | [0.875, −0.75] |
| 2.375 | [−1, 1] | [0, 1] |
| 3.375 | [−1, 1] | [−1, 1] |

更新の間の5記録点では同じ値を保持します。下降1の成分0は3.375秒、上昇2の成分1は2.375秒に新しい目標値へ到達します。このサンプルでは増分を二進数で正確に表せるため、全151点を独立式へ完全一致で照合します。

RK45ではこのブロックの更新時刻も積分区間の境界に含めます。微分評価や刻み棄却で出力を更新せず、記録時計の整数tickで1回だけ更新します。異なる整数周期の入力表と組み合わせた現在入力の取得、同じ周期のRate Limiter直列接続、Unit Delayの前回サンプル出力も検証します。自身への直接帰還を解く代数ループ処理は実装していません。

連続プラントへ接続した応答は、各保持区間の独立した一次遅れ解析式と照合します。RK45の棄却を実際に発生させ、その間も制限値の更新が増えないことを確認します。速度×周期と最終出力を検査し、非常に大きな有限値では候補上下限を先に計算せず、入力間の差が表現範囲を超える場合も有限の制限増分で更新します。

選択Scopeの祖先に含まれると、非線形ブロックとして連続／離散Bode・状態空間解析を拒否します。別のScopeの祖先にない場合はその線形解析を妨げません。詳細な実行結果と途中の失敗は[検証記録](validation.md)へ記載します。
