# Dead Zone

Dead Zoneは両端を含む不感帯内の入力を0にし、外側の超過分を出力します。状態や保持周期を持たず、各成分へ独立に同じ範囲を適用します。

| 入力u | 出力 |
|---|---|
| u < lower | u − lower |
| lower ≤ u ≤ upper | 0 |
| u > upper | u − upper |

たとえば下端−0.2・上端0.3なら、入力−0.8は−0.6、−0.25は−0.05、−0.2から0.3までは0、0.65は0.35です。範囲外の入力を端の値へ丸めるSaturationとは出力の式が異なります。

## 設定と保存

ブロック種類から「Dead Zone」を追加し、「不感帯の下端」「不感帯の上端」と信号幅を設定します。既定の範囲は[−0.1, 0.1]、信号幅は1。下端・上端は必須の有限スカラーで、下端≤上端です。範囲が0を含む必要はなく、同じ値の両端も許します。[0,0]なら出力は入力と同じ、[1,1]なら出力は入力−1になります。幅は1〜64、入力と出力の幅は同じです。

```json
{"kind":"dead_zone","lower":-0.2,"upper":0.3}
```

通常のモデル保存・ファイル書き出し／読み込み・Undo／Redo・コピー・サブシステム内部で設定を保持します。既存のグラフ保存形式を使用します。以前のモデルに新しい項目を追加せず、既存ブロックの既定値を変えません。空欄、null、逆転した両端、不足／未知の項目は拒否し、直前のモデルと結果を保持します。

有限入力と両端からの引き算が浮動小数の範囲を超える場合は、演算時刻とブロックIDを含む実行エラーになります。たとえば[−1e308,−1e308]に入力1e308は出力を表せません。[−1e308,1e308]の範囲内は0であり、両端の差を先に計算してオーバーフローさせません。

## サンプルと検証

[2成分サンプル](../samples/graphs/dead-zone.json)はGUIの「ベクトル + Dead Zone」から開けます。8行の入力を0.1秒ごとに保持して繰り返し、記録刻み0.01秒・終了1.6秒で全161点を取得します。元の入力と処理後の出力を別のScopeへ記録します。

| 行 | 入力 | 出力（下端−0.2・上端0.3） |
|---|---|---|
| 0 | [−0.8, 0.8] | [−0.6, 0.5] |
| 1 | [−0.25, 0.25] | [−0.05, 0] |
| 2 | [−0.2, 0.3] | [0, 0] |
| 3 | [−0.05, 0.05] | [0, 0] |
| 4 | [0, 0] | [0, 0] |
| 5 | [0.15, −0.15] | [0, 0] |
| 6 | [0.3, −0.2] | [0, 0] |
| 7 | [0.65, −0.65] | [0.35, −0.45] |

1周期の16成分値では、非ゼロ値が入力14個から出力5個になります。これはこの入力と設定での数値で、ノイズを一般に除去できる保証ではありません。終端取得点を周期内の保持区間へ重複加算しません。

RK4／RK45の演算と連続状態への接続に対応し、記録時計の間で切り替わるStepからDead Zone・Integratorへ接続した結果も独立した積分式と照合します。Dead Zone固有のゼロクロッシング検出やヒステリシスは実装していません。

非線形ブロックなので、選択したScopeの祖先に含まれると連続／離散Bode・状態空間解析は拒否します。[0,0]も自動で線形化しません。別のScopeの祖先にないDead Zoneは、その線形解析を妨げません。検証結果は[検証記録](validation.md)に記載します。
